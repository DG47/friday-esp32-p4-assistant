# Owner-approved read-only project reports

Default-off production integration extends the durable task/Telegram core from draft
PR #9. The same task ID is shared by the authenticated device dispatcher and configured
Telegram owner. No second generic agent job is created. PR #9 remains open and untouched;
merging both requires deliberate reconciliation of the shared modules.

A trusted operator enrolls canonical source roots and explicit nonsecret relative files.
No-follow descriptor walks reject traversal/symlinks; reads reject hidden/secret paths,
hardlinks, unsupported extensions, nonregular and non-UTF8 files. Bounds are 32 files,
64 KiB/file and 1 MiB total. Private state/artifact roots are separate from source.
Existing database/WAL/SHM files reject links, foreign owners and public permissions.
SQLite assumes no hostile same-user process concurrently mutates those private paths.

The local-only planner sees goal/alias/capabilities, not source contents. A single enum
proposal chooses inventory, README excerpt and source statistics or refuses unsupported
intent. A narrow deterministic English gate rejects known unsupported operations before
inference. General semantic understanding is not established. The executor never gains
arbitrary shell, source edits, generated-code execution or network privileges.

Exact approval scope includes file hashes/bytes/lines, executor fingerprint, operations,
sections, write destination and limits. Owner/revision/digest/nonce approval expires after
300 seconds and follows full-scope review. Trusted loopback admin or a fully delivered
configured Telegram scope can approve; native generic “yes” cannot. The device summary
cannot replace complete review. Concurrent expired-scope refreshes retry safely.

The worker persists write intent, reads only enrolled files, renders inert bounded text,
exclusively writes one private report, fsyncs and verifies the artifact hash and unchanged
source manifest. Stop revokes admission and drains admitted work; leftover bytes may be
quarantined. Uncertain/stopped work is not completed or claimed physically reversed.
Interrupted planning/execution is never automatically replayed.

Existing WebSocket utterance, Recover/Stop and result ACK paths project the durable task.
Protected memory/reminder confirmation takes priority. Reconnect requires explicit
Recover under a fresh epoch/request. Unacknowledged terminal results retain delivery ID;
acknowledged results restore a surface only. Stop controls are device/task/generation-bound.

Startup obtains task-supervisor ownership, then a private Telegram config-directory
consumer lock before binding mutation. Transport/runtime failure blocks new admission
and approval. The production connector is implemented and default off; the rehearsal
transport remains mock-only. Source/report bodies remain local. See
[secure local setup](../report-telegram-setup.md) for dedicated bot, protected token entry,
verified numeric owner identity, durable offsets, uncertain sending and bounded retry.

[Validation summary](current-updates-validation.md) distinguishes actual local-model and
native protocol/build checks from mocked Telegram and physical acceptance. Raw logs,
private configuration/state, source folders and model/firmware binaries are excluded.
Opt-in evaluators generate original synthetic content. No required firmware delta exists;
optional repeated-tap feedback can add `strncmp(action,"reportstop:",11) == 0 ||` to
its mutation predicate, but backend fencing does not require it and it is not applied.

The owner must choose exact supported nonsecret real files, bind the physically paired
device and privately configure a verified dedicated bot when ready. There is no project-
picker UI. Folder/account/token handoffs and real device/live Telegram acceptance remain;
ordinary authorized code publication/deployment does not need a new permission gate.
