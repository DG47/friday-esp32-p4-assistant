# Trusted fixed-fixture local execution

`LocalTaskStore` and `LocalTaskWorker` extend the same persistent task domain used by the phone harness and offline Telegram adapter. The planner remains deterministic. Only the registered `range-total` fixture is accepted: a small original Python source file and unittest file created in a private per-task directory under the explicitly configured fixture root. The test command uses the installed Python standard library; there are no dependencies to install and no network calls. Production Friday does not import or run this executor.

The approved scope contains the exact argv, executor/template digests, fixture root, operations, bounded writes, runtime/output limits and explicit unsafe-for-untrusted-code profile. No user/model/Telegram text supplies commands, arbitrary arguments, filenames or a project root. The local control harness can construct the Local store/worker instead of the arithmetic store/worker, preserving task IDs, evidence, questions, expiry, revision, fencing, cancellation and duplicate actions.

The actual lifecycle inspects the disposable files, runs the existing seeded unittest (exit1, assertion `6 != 10`), records the deterministic diagnosis, atomically replaces only `range_total.py` with its fixed registered bytes, and reruns the same command (exit0). Commands, cwd, bounded stdout/stderr, exit codes, hashes and a unified diff are persisted as task evidence. Unexpected startup/test failures end as failed with command evidence. It is not a general reasoning agent.

The runner validates resolved paths, rejects symlink roots/parents/task paths/files and unexpected files, accepts only the original or patched source bytes and exact test bytes, and launches without a shell using a closed argv and scrubbed environment. The child uses isolated Python, disables site imports and bytecode writes, and sets a3-second alarm before running trusted tests. The supervisor also enforces a4-second wall deadline,8192-byte combined output bound, cancellation/lease checks, process-group termination and wait before reporting stopped. The test process is read-only. The parent patch is fenced against Stop/lease expiry under the store transaction and uses an atomic fixed-byte replacement.

This is NOT a safe sandbox for untrusted or generated code. The allow-default profile permits process replacement and system runtime reads; denied individual probes do not prove complete containment. Generated source and arbitrary commands are rejected structurally. Raw executor output remains local and transport withholds it by default.

macOS sandbox-exec is mandatory and fails closed if unavailable or startup fails. Its tested profile denies network connections, child forks, filesystem writes and reads of personal/project trees (`/Users`, `/Volumes`, temporary user directories) except the exact task fixture. System runtime reads outside the fixture remain available. A blanket file-read deny blocked even macOS runtime startup; no unrestricted fallback was used. This profile plus the registered-byte/argv boundary is suitable only for this fixture. It is not a security proof for hostile user-selected source, an unrestricted filesystem jail, or a production runner. Private root ownership is assumed: another same-user process actively replacing directory entries is outside this proof, and would require descriptor-based or stronger OS containment.

Recovery replays registered read-only checks only when no unresolved owned/launching process record exists. Unresolved ownership becomes uncertain and blocks retirement; an absent in-memory worker is never termination proof. The child's own alarm prevents a crashed supervisor leaving the registered test indefinitely alive; lease recovery occurs after the longer30-second lease. Patch replay recognizes the exact already-patched bytes, and does not rewrite or repeat side effects after the filesystem/SQLite commit gap. A pending byte prefix of the exact registered replacement can be discarded and rebuilt; any other partial bytes fail closed. No real external side effects are replayed. Tests simulate a crash after patch replacement before evidence commit and confirm unchanged modification time on recovery. This is not proof of power-loss durability or recovery for arbitrary child commands.

Eleven local-executor tests include actual failing/passing subprocess runs, process reaping after running Stop, crash-gap recovery, changed approval, expired patch authority, symlink escape rejection, duplicate Telegram delivery preserving one local task, startup failure evidence, and real sandbox read/write/network/fork denial probes, oversized-output termination and an independent child-watchdog check. Evidence export runs only this registered fixture: `scripts/export_local_task.py`.

Remaining gap to user-selected projects: separately authorize one concrete project/root and typed operations; validate code provenance; provide an OS boundary for untrusted code and dependency/runtime access; replace the fixed patch with reviewed planning; implement durable child identity and robust supervisor recovery; define uncertain non-idempotent actions; establish authenticated clients and safe delivery. No access to a user's unrelated projects, apps, files, accounts or secrets was exercised. No deployment, firmware flash, live Telegram or paid model call occurred. VAD remains unresolved.
