# Personal Music display v2

Backend candidate only; no live application, account reads, playback mutations or firmware flashing were performed for this change.

Clients declare `media_updates_v1`, plus `media_persistent_v1` for retained overlay ownership and `media_artwork_v1` for the 131072-byte JSON frame budget. Music has `expires_ms:null`; it ends on explicit dismissal or disconnect. A priority overlay suspends updates and retains ownership. Polling and artwork retrieval stop when all views suspend. Legacy clients retain their prior priority-interruption behavior.

Priority messages attach a per-peer root `media_overlay` containing `media_request_id`, `media_session_id`, `overlay_id`, `media_sequence`, and `state:"suspend"`. Native sends `type:"media.resume"` with the three identity fields. Backend sends `type:"media.resume.result"` with those fields and `status:"pending"|"ignored"|"ready"`. Pending or ignored must preserve suspension. Ready precedes a fresh owned media frame with sequence greater than the suspend sequence. Protected reminders require a valid acknowledgment; confirmations require actual resolution and idle. Close/TTL alone cannot clear either barrier. Explicit Music dismissal is ordinary `scene.action` dismiss; overlay close uses `media.resume`.

Artwork requires `MUSIC_ARTWORK_ENABLED=true` separately from Spotify account opt-in. It is off by default. The backend accepts only official playback `album.images` URLs matching `https://i.scdn.co/image/<40 lowercase hex>`. The dedicated HTTP client has no credentials, cookies, environment proxy, or redirects. Transport request logs are suppressed. Input is bounded to 256KiB and 1024 pixels per side/1MP, JPEG or PNG, one frame with verified dimensions. Full artwork is resized with preserved aspect ratio and neutral letterboxing; metadata, controls and Spotify attribution belong outside the image. Spotify policy reference: https://developer.spotify.com/documentation/design

Every artwork-capable surface carries opaque `track_key` and `artwork_generation`. Its `artwork` carries the same `track_key`, `width:192`, `height:192`, `format:"rgb565_le"`, `status:"loading"|"unavailable"|"ready"`. Ready includes lowercase SHA256 of decoded 73728 bytes. `data_base64` is exactly 98304 characters and is sent for a new asset/view, then omitted for unchanged cached content. New view/reconnect resends. Loading/unavailable invalidates the old image. Native validates owner, sequence, track, generation, dimensions and hash before accepting pixels. Track changes, priority suspension and final dismissal invalidate artwork acceptance; a late provider response cannot resurrect dismissed ownership. Cache holds at most four decoded images, 320KiB, in private memory and clears on final dismissal.

Pillow 12.3.0 is pinned in backend requirements. Installing it into the live environment and enabling artwork are future deployment actions, not part of this isolated candidate.
